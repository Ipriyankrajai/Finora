**Scheduled Task:** `generateRecurringTransactions`

```typescript
export const generateRecurringTransactions = schedules.task({
  id: "generate-recurring-transactions",
  cron: "0 * * * *", // Every hour
  run: async (payload) => {
    const now = payload.timestamp;

    // Find all active rules where nextOccurrenceDate <= now
    const dueRules = await db.recurringRule.findMany({
      where: {
        status: "ACTIVE",
        nextOccurrenceDate: { lte: now },
      },
      include: {
        tags: true,
      },
    });

    logger.info(`Found ${dueRules.length} due recurring rules`);

    let totalGenerated = 0;

    for (const rule of dueRules) {
      const generated = await generateOccurrencesForRule(rule, now);
      totalGenerated += generated;
    }

    logger.info(`Generated ${totalGenerated} transactions from ${dueRules.length} rules`);

    return { rulesProcessed: dueRules.length, transactionsGenerated: totalGenerated };
  },
});
```

**Generation function:** `generateOccurrencesForRule`

This is the core logic. For each rule, iterate from its `nextOccurrenceDate` forward until reaching `now`:

1. While `currentDate <= now`:
   a. Check end conditions: if `rule.endDate && currentDate > rule.endDate`, break. If `rule.maxOccurrences && rule.completedCount >= rule.maxOccurrences`, break.
   b. Check idempotency: query `db.recurringOccurrence.findUnique` with the composite key `{ ruleId_scheduledDate: { ruleId, scheduledDate: currentDate } }`. If exists, skip (already generated).
   c. If not exists, wrap in `db.$transaction`:
     - Create Transaction with userId, type, amountCents, date=currentDate, description, currencyCode from the rule. Do NOT set recurringRuleId on Transaction directly (the link is through RecurringOccurrence).
     - Copy tags: if `rule.tags.length > 0`, use `tx.transactionTag.createMany` with the tag IDs mapped from rule.tags.
     - Create RecurringOccurrence with ruleId, scheduledDate=currentDate, status="GENERATED", transactionId=created.id.
     - Increment completedCount and set lastGeneratedDate on the rule.
   d. Advance currentDate via `computeNextOccurrence(rule.frequency, currentDate, rule.dayOfMonth ?? undefined)`.

2. After the loop, update the rule's `nextOccurrenceDate` to `currentDate` (the next future date).

**Important edge cases to handle:**
- If a rule was paused and resumed, `nextOccurrenceDate` is reset to today by the resume mutation (Plan 04), so no backlog accumulation happens here. But if somehow there's a small gap (e.g., 2-3 missed daily occurrences), generate them all.
- Never generate more than 100 occurrences per rule per run (safety limit to prevent runaway loops). Log a warning if this limit is hit.
- Handle BigInt correctly: do NOT pass BigInt in any logger arguments (convert to Number or String first for logging).
