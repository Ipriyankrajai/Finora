Run `bunx prisma generate` to regenerate the client, then `bunx prisma db push` to apply the schema.

**2. Create `packages/api/src/lib/recurring.ts`:**

Create a pure function `computeNextOccurrence` that takes:
- `frequency: "DAILY" | "WEEKLY" | "BIWEEKLY" | "MONTHLY" | "YEARLY"`
- `currentDate: Date`
- `anchorDay?: number` (original day-of-month for MONTHLY rules, to prevent drift)

Implementation:
- DAILY: `addDays(currentDate, 1)`
- WEEKLY: `addWeeks(currentDate, 1)`
- BIWEEKLY: `addWeeks(currentDate, 2)`
- MONTHLY: Use `addMonths(currentDate, 1)`, then if `anchorDay` is provided, clamp to `Math.min(anchorDay, getDate(lastDayOfMonth(nextMonth)))` and use `setDate`. This prevents the month-end drift pitfall (e.g., Jan 31 -> Feb 28 -> Mar 28 instead of Mar 31).
- YEARLY: `addYears(currentDate, 1)`

Import from `date-fns`: `addDays`, `addWeeks`, `addMonths`, `addYears`, `setDate`, `lastDayOfMonth`, `getDate`.

Also export a helper `computeInitialNextOccurrence` that takes a rule's frequency, startDate, dayOfWeek, and dayOfMonth, and returns the first nextOccurrenceDate (which is just the startDate itself if startDate is today or in the future, or the next valid date if startDate is in the past). This is used when creating a new rule.

**1. Create `packages/api/src/schemas/recurring.ts`:**

Follow the pattern from `packages/api/src/schemas/transaction.ts`. Import `moneyInput` and `notesInput` from `./transaction`.

Create and export:
- `recurringFrequency`: `z.enum(["DAILY", "WEEKLY", "BIWEEKLY", "MONTHLY", "YEARLY"])`
- `createRecurringRuleInput`: z.object with fields:
  - `type`: `z.enum(["INCOME", "EXPENSE"]).default("EXPENSE")`
  - `amount`: `moneyInput`
  - `description`: `notesInput.default(null)`
  - `frequency`: `recurringFrequency`
  - `dayOfWeek`: `z.number().int().min(0).max(6).optional()` (0=Sunday..6=Saturday)
  - `dayOfMonth`: `z.number().int().min(1).max(31).optional()`
  - `startDate`: `z.coerce.date()`
  - `endDate`: `z.coerce.date().optional()`
  - `maxOccurrences`: `z.number().int().min(1).optional()`
  - `tagIds`: `z.array(z.string().cuid()).optional()`
  Add two refinements:
  1. WEEKLY/BIWEEKLY requires dayOfWeek (return false if frequency is WEEKLY or BIWEEKLY and dayOfWeek is undefined)
  2. Cannot have both endDate and maxOccurrences (mutually exclusive)

- `updateRecurringRuleInput`: z.object with `id: z.string().cuid()` and all other fields optional. Same refinements but only when both frequency and dayOfWeek are present.

**2. Create `packages/api/src/routers/recurring.ts`:**

Follow the pattern from `packages/api/src/routers/transaction.ts`. Import `protectedProcedure, router` from `../index`, `db` from `@finora2/db`, `TRPCError` from `@trpc/server`, schemas from `../schemas/recurring`, `displayToCents` from `../lib/money`, and `computeNextOccurrence` from `../lib/recurring`.

Create and export `recurringRouter` with these procedures:

- `list`: protectedProcedure query. Fetches all recurring rules for the user, ordered by createdAt desc. Include `tags` relation (with nested `tag` include). Return the full list (no pagination needed for recurring rules — users won't have hundreds).

- `getById`: protectedProcedure with input `z.object({ id: z.string().cuid() })`. Fetch rule with tags and recent occurrences (last 5). Verify ownership, throw NOT_FOUND if missing or wrong user.

- `create`: protectedProcedure with input `createRecurringRuleInput`. Mutation that:
  1. Converts amount to cents via `displayToCents`
  2. Determines `dayOfMonth` for MONTHLY rules from startDate if not explicitly provided
  3. Computes initial `nextOccurrenceDate` (the startDate itself)
  4. Creates the RecurringRule in a `db.$transaction` block
  5. Creates RecurringRuleTag entries if tagIds provided
  6. Returns the created rule with tags

- `update`: protectedProcedure with input `updateRecurringRuleInput`. Mutation that verifies ownership, updates fields that are provided, handles tag replacement (delete existing + create new if tagIds provided), returns updated rule.

- `delete`: protectedProcedure with input `z.object({ id: z.string().cuid(), deleteTransactions: z.boolean().default(false) })`. If deleteTransactions is true, delete all linked transactions first (via RecurringOccurrence.transactionId), then delete the rule (cascade handles RecurringRuleTag and RecurringOccurrence). If false, just delete the rule (cascade removes tracking but generated transactions remain as orphaned standalone transactions).

- `todayGenerated`: protectedProcedure query. Count RecurringOccurrence records where `rule.userId = currentUser`, status = "GENERATED", and generatedAt is today (between start of day and start of tomorrow). Return `{ count: number }`.
