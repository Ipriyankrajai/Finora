  <files>
    packages/db/prisma/schema/auth.prisma

  <action>
    1. **Extend User model** in `packages/db/prisma/schema/auth.prisma`:
       - Add `hasCompletedOnboarding Boolean @default(true)` — existing users default to true (they don't need onboarding). New users will be set to false explicitly.
       - Add `currencySymbol String @default("$")` — display preference only, does not affect stored amounts.
       - Place both fields after `updatedAt`, before `sessions`.

    2. **Run migration**: `cd packages/db && bun run db:push` (or `bunx prisma db push` if that's the command pattern). Then `bun run db:generate` to regenerate the Prisma client.

    3. **Enable deleteUser** in `packages/auth/src/index.ts`:
       - Add `user: { deleteUser: { enabled: true } }` to the betterAuth config object, after `emailAndPassword`.

    4. **Create user schemas** at `packages/api/src/schemas/user.ts`:
       - `updateProfileInput`: z.object({ name: z.string().min(2).max(100) })
       - `updateCurrencyInput`: z.object({ currencySymbol: z.string().min(1).max(3) })
       - Follow the exact pattern from `packages/api/src/schemas/tag.ts`.

    5. **Create user router** at `packages/api/src/routers/user.ts`:
       - Follow the pattern from `packages/api/src/routers/tag.ts`.
       - Import prisma from `@finora2/db`, import `protectedProcedure, router` from `../index`.
       - 4 endpoints:
         - `getSettings`: protectedProcedure.query — select id, name, email, currencySymbol, hasCompletedOnboarding from User where id = ctx.session.user.id
         - `updateProfile`: protectedProcedure.input(updateProfileInput).mutation — update name via prisma.user.update. Do NOT use better-auth updateUser (known Prisma v7 bug #6469).
         - `updateCurrency`: protectedProcedure.input(updateCurrencyInput).mutation — update currencySymbol via prisma.user.update.
         - `completeOnboarding`: protectedProcedure.mutation — set hasCompletedOnboarding to true via prisma.user.update.

    6. **Register user router** in `packages/api/src/routers/index.ts`:
       - Import `userRouter` from `./user`.
       - Add `user: userRouter` to the appRouter.
  </action>
  <verify>
    - `bunx prisma validate` passes in packages/db
    - `bun run build` succeeds (or `bun run typecheck` if available) to confirm router types are correct
    - Check that `packages/api/src/routers/index.ts` includes `user: userRouter`
  </verify>
  <done>
    User model has hasCompletedOnboarding and currencySymbol fields. User tRPC router has 4 endpoints (getSettings, updateProfile, updateCurrency, completeOnboarding). Auth config enables deleteUser. All using direct Prisma queries, not better-auth updateUser.
  </done>

    1. **Modify formatCents** in `apps/web/src/lib/format.ts`:
       - Add optional `symbol` parameter defaulting to `"$"`: `formatCents(cents: bigint | number, symbol = "$"): string`
       - Change from `Intl.NumberFormat` with `style: "currency"` to `style: "decimal"` with minimumFractionDigits/maximumFractionDigits 2.
       - Prepend the symbol manually: `return \`${symbol}${formatted}\``
       - Handle negative values: format absolute value and prepend `-` if negative.
       - This preserves thousand separators and decimal formatting from Intl while allowing custom symbols.

    2. **Create CURRENCY_SYMBOLS constant** — add to `apps/web/src/lib/format.ts` (or a separate constants file if preferred):
       ```

         { value: "£", label: "£ - British Pound" },

         { value: "₩", label: "₩ - South Korean Won" },
       ] as const;
       ```

    3. **Create user settings hooks** at `apps/web/src/hooks/use-user-settings.ts`:

       - `useUpdateCurrency()`: calls `trpc.user.updateCurrency.useMutation()` with onSuccess that invalidates `trpc.user.getSettings` and shows `toast.success("Currency updated")`.
       - `useCompleteOnboarding()`: calls `trpc.user.completeOnboarding.useMutation()` with onSuccess that invalidates `trpc.user.getSettings`.
